## 1. アプリの目的

- 複数のサブスクを契約していると、契約中のサービスで「見たい作品」がどれだけ実際に視聴できるかを把握できていない。
- 見たい作品を検索するたびに、契約している複数サービスをひとつずつ開いて確認する手間がある。
- 配信状況は変動するため、各サービス側の一覧ページだけでは「今すぐ見られるか」を正確に把握しづらい。
- 本アプリは、ユーザーが契約しているサブスクを登録し、見たい作品リストと突き合わせることで「契約しているサブスクが、自分の見たい作品にどれだけ対応しているか 」を可視化する。

## 2. ユーザー要件

- 見たいアニメのタイトルを検索し、配信中のサービス一覧をすぐ確認したい。
- 見たい作品をリストにためておき、契約状況と照らし合わせて管理したい。
- 契約しているサブスクが「見たいリストの中でどれだけ活用されているか」を確認し、契約継続の判断材料にしたい。

## 3. 機能要件

### 全画面共通機能

- タイトルアイコン「ドコアニ」をクリックすることでトップ画面に遷移する。

### ユーザー認証機能

- メールアドレスとパスワードで会員登録できる。
- メールアドレス宛に送信された確認用URLをクリックすることで本登録が完了する（Laravel標準のメール認証機能を利用）。
- 登録済みメールアドレスとパスワードでログインできる。
- ログアウトできる。
- パスワードを忘れた場合、登録済みメールアドレス宛にパスワード再設定用URLを送信できる。
- 登録用URL、再設定用URLの有効期限は発行から60分とする。
- 会員登録はLaravel Breeze標準の流れ（名前・メールアドレス・パスワードを入力 → 確認メールのURLをクリックして本登録完了）とする。
- 契約サービス・月額料金は、会員登録後にマイページの設定タブから登録する（会員登録時の同時登録はMVP後に対応）。
- 月額料金は0円を許可せず、1円以上の整数のみ入力できる（Laravel Form Requestでバリデーション：integer, min:1）。

### トップ画面機能

- 人気度（popularity）降順で上位6件のアニメ作品を一覧表示する。 表示レイアウトはスマートフォン（768px未満）で2列×3行、 PC（768px以上）で6列×1行とする。
- 表示に使用するデータは、既存の日次バッチで取得・保存済みのpopularity値であり、 画面表示のためにTMDB APIへリアルタイム問い合わせは行わない。
- サイトの使い方を3ステップ程度のテキストで説明するセクションを表示する。（静的な内容にする）

### 検索機能

- 作品名を一部入力すると、候補がドロップダウンで表示される。（あいまい検索）
- あいまい検索で表示されたアニメ作品に見たいリスト、視聴済みリストに追加できるボタンも表示される。（ログイン済みの時）
- 見たいリスト、視聴済みリストボタンは、追加済みなら背景色を黒、未追加なら背景色を白にする。
- 候補をクリックするとアニメ詳細画面に遷移する。
- Enterキーまたは検索ボタン押下で検索結果一覧画面に遷移する。
- 未ログインでも検索・アニメ詳細は閲覧は可能。

### 検索結果一覧機能

- 検索ボタン押下で表示される。
- アニメ作品をクリックすることで、各アニメ詳細画面に遷移する。
- 配信中サービスを表示しており、クリックすると各配信サービスに遷移する。
- アニメ作品に見たいリスト、視聴済みリストに追加できるボタンも表示される。（ログイン済みの時）
- 見たいリスト、視聴済みリストボタンは、追加済みなら背景色を黒、未追加なら背景色を白にする。
- 自DB内の検索結果が0件の場合、「情報がありません」と表示する（TMDB APIへのリアルタイム問い合わせは行わない）。

### アニメ詳細機能

- 上部に検索バー（機能は検索機能と同じ）
- アニメタイトル、ポスター画像、あらすじを表示する。
- 配信サービスのロゴ（TMDBから取得）を表示し、ロゴをクリックすることで、配信サービスのトップページに遷移する。（ここはTMDB APIは提供できないので、主導で用意する）
- 配信状況フィルター （すべて／サブスクリプション／無料／レンタル／契約外） を付け、各項目で絞り込みができます。
- 「契約外」とは、いずれかの配信サービスで配信されているが、ユーザーが契約していないサービスのみで配信されている状態を指す。
- 未ログイン時の配信状況フィルターは契約外はなし。
- 見放題は配信サービスのロゴ+緑の枠線（ログイン済みのみ）
- レンタル（追加課金）は配信サービスのロゴ+オレンジの枠線（ログイン済みのみ）
- 契約外、未ログインは配信サービスのロゴ+グレーの枠線
- 「最終更新日」を表示し、配信情報が取得された日時を明示する（TMDB側の同期遅延を考慮）。
- マイページに遷移できる。（未ログイン時はなし）
- 見たいリストへの追加・削除ができる。（未ログイン時はなし）
- 視聴済みリストへの追加・削除ができる。（未ログイン時はなし）
- 見たいリスト、視聴済みリストボタンは、追加済みなら背景色を黒、未追加なら背景色を白にする。

### マイページ

- 見たいリスト、視聴済みリスト、契約状況、設定タブ
- 見たいリストと視聴済みリストは排他的な状態として管理し、1作品につきどちらか一方の状態を持つ。
- 視聴済みリストから見たいリストに戻したとき、優先度は一番下になる。
- 退会時、本人の見たいリスト・視聴済みリスト・マイサブスク登録データは物理削除する。 ※他ユーザーが参照するデータが存在しないため、匿名化保持は不要。

#### 見たいリスト機能

- 作品を見たいリストに追加できる（同一作品の重複追加は不可。ユーザーID×作品IDで一意制約）。
- リストは作品名・ポスター画像・配信サービス（ロゴアイコンのみ）を一覧表示する。
- 優先度を設定・並び替えできる。
- 契約中サービスのアイコンで絞り込みできる（複数選択可）。
- 視聴済み（視聴済みリスト）へ切り替えられる（状態変更であり、削除ではない）。
- リストから削除できる（削除は状態変更とは別の操作となる）。

#### 視聴済みリスト機能

- 視聴済み作品の一覧を確認できる。
- リストは作品名・ポスター画像・配信サービス（ロゴアイコンのみ）を一覧表示する。
- 「まだ見てない」を選択すると見たいリストへ戻せる（状態変更）。
- リストから削除できる（削除は状態変更とは別の操作として提供する）。

#### 契約状況機能

- 契約中サービスごとに、月額料金と「見たいリストの中で視聴可能な本数」を表示する。
- どのサブスクでも視聴できない（flatrateが1つも無い）作品の本数を表示する。
- 割合や費用対効果指標は表示せず、本数のみのシンプルな表示に留める。

#### 設定機能

- 登録済みサービスの追加・料金変更・削除ができる。
- サービスは1件ずつ追加・削除する。編集できるのは月額料金のみとし、サービスを変更する場合は削除して追加し直す（複数件の一括編集はMVP後に対応）。
- 料金変更時に過去の料金履歴は保持しない。契約状況タブには常に「現在の料金」のみを表示する。
- 登録する月額料金は自己申告制とし、実際の請求額との差異について本アプリは正確性を保証しない。料金変更時はユーザー自身が任意のタイミングで修正するものとし、自動での価格取得・追従は行わない。
- 同一サービスの重複登録はできない（ユーザーID×サービスIDで一意制約）。
- パスワード変更ができる（現在のパスワード入力による本人確認必須）。
- 退会することができる（アカウント削除）

## 4. 非機能要件

### セキュリティ

- パスワードはハッシュ化して保存する。
- 通信はHTTPS化する。
- Laravelの標準CSRF保護機能を有効化する。
- XSS対策としてBladeのエスケープ機能を利用する。
- 見たいリスト・視聴済みリスト・マイサブスク情報は本人のみ閲覧・編集できる（Laravelの認可機能Policy／Gateで制御）。
- 例外エラー発生時、Laravelのデバッグ画面を出さず、404, 419, 500, 503を対象に専用エラーページを表示する。
- ユーザー入力はLaravelのForm Requestでバリデーションを行う（必須項目、文字数上限、URL形式など）。
- DB操作はEloquent ORM（プレースホルダ使用）を利用し、SQLインジェクションを防ぐ。
- 同一メールアドレスへのログイン失敗が5回連続した場合、15分間ログインを制限する（Laravelの標準機能であるRateLimiterを利用する）。
- パスワード変更時は、現在のパスワードの入力による本人確認を必須とする。

### レスポンシブ対応

- 画面幅375px（スマートフォン）〜1920px（PC）の範囲でレイアウトが崩れないこと。
- ブレークポイントは768px未満をスマートフォン向けレイアウトとする。

### パフォーマンス

- 登録件数1.5万件（日本アニメの総数）、同時アクセス30ユーザー（個人開発の一般的な平均ユーザー）を想定した場合、自DB内のタイトル検索結果は5秒以内に返す。

### 外部API連携

- 作品情報・配信情報はTMDB APIから取得し、PostgreSQLに保存する。検索を含む画面表示は常に保存済みデータを使用し、ユーザーの操作をトリガーにAPIへ問い合わせることはない。
- 作品情報・配信情報の取得はバッチ処理（Laravel Task Scheduling、routes/console.php）で行い、以下の2種類を定期的に実行する。
  1. 新規タイトルの取り込み：TMDBのdiscover/tvエンドポイントを「ジャンル＝アニメーション（genre_id=16）」かつ「制作国＝日本（origin_country=JP）」で絞り込み、人気度の高い順（sort_by=popularity.desc）に上位50ページ（約1,000件）を対象とする。discover APIは最大500ページ（1万件）までしか取得できない仕様のため、全件取得（約1.5万件）は対象期間を分割して取得する方式で、MVP後に対応する。1日1回実行し、自社DB未登録のタイトルのみを新規保存する。新規保存時に、その作品の配信情報（watch/providers）も同時に初回取得する。
  2. 既存タイトルの配信情報更新：登録済みの全タイトルを対象に、配信情報（watch/providers）を再取得し更新する。週1回、決まった曜日・時刻（例：毎週月曜3:00）に実行し、1回のバッチ実行で登録済み全件を処理する。
- MVPではTV作品のみを対象とし、配信情報の取得には作品全体単位のエンドポイント（/tv/{series_id}/watch/providers）のみを使用する。劇場版（映画）作品はMVP後に対応する。TMDBではTV作品と映画作品でIDが重複する可能性があるが、TV作品のみであれば既存のテーブル設計のまま一意性を保てる。また、シーズン単位のエンドポイント（`/tv/{series_id}/season/{season_number}/watch/providers`）は使用しない。本アプリのテーブル設計（anime_titlesにシーズンの概念を持たない）に対応させるための設計判断である。
- 既存タイトル更新バッチは、TMDBのレート制限（目安：1秒あたり約40リクエスト）を守った場合でも、登録済み全件（MVP時点で約1,000件）の処理は約5分で完了する見込みのため、上限件数や分割処理は設けず、1回の実行内で全件を処理する。
- バッチが万一長時間化し、次回の実行開始時刻と重なった場合に二重起動しないよう、Laravelの`withoutOverlapping()`を使用する。
- 配信情報の同期には最大1週間程度の遅延が生じる場合があるため、画面に「最終更新日」を表示する。
- 新規タイトルの反映にも次回バッチ実行までの遅延が生じる（検索した瞬間には反映されない）。
- TMDB API利用規約に基づき、提供元クレジット（TMDB／JustWatch）をフッター等に表示する。
- 各配信サービスへのリンクは、作品個別ページへの直接遷移（ディープリンク）ができない場合があるため、サービスのトップまたは検索結果ページへの遷移とする。
- 新規タイトルの初回取得（あらすじ・画像・配信情報・人気度のいずれか）に失敗した場合、当該タイトルはDBに保存しない。翌日のバッチで自社DB未登録タイトルとして自動的に再取得対象となる。
- バッチ処理中に既存タイトルの情報取得が失敗・タイムアウトした場合、あらすじ・画像を空欄のまま保存し、当該タイトルの最終更新日（last_synced_at）は更新しない（次回バッチで優先的に再取得対象となる）。
- バッチ更新時は、TMDB APIのレート制限（目安：1秒あたり約40リクエスト）を超えないよう、リクエスト間隔を制御する。

### データ管理方針

- 取得した作品情報・配信情報はPostgreSQLに保存し、TMDB APIへの再問い合わせは行わない。
- ユーザーの見たいリスト・視聴済みリスト・マイサブスク情報は、退会時に物理削除する。
- 配信情報の誤りはTMDB提供データに準拠し、本アプリ側での手動修正は行わない。

### このサービスを利用しようと思った理由・きっかけは？

複数のサブスクに加入しており、ひとつひとつのサービスでアニメを検索するのが面倒だったため。追加でNetflix・U-NEXT・Amazon Prime Video・Disney+・dアニメストアの5つを契約している状況で、SNSでおすすめされた作品を見るたびに5つのアプリを順番に開いて検索しており、どこにもなかったり、あってもレンタル（有料）だったりして時間を無駄にしていた。
