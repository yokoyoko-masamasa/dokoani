# MVP 決定事項

決定日: 2026-09-20
方針: **MVP は必須機能（A の43件）に絞り、完成を優先する。**

## 1. 範囲

- MVP は `docs/features.md` の **A（MVP必須）43件だけ**を作る。
- B（付加機能）15件・C（後回し）3件は作らない。B は MVP の完成後に追加する。
- B・C の準備のための実装（将来用の画面・列・関数）も、MVP では作らない。
- 例外: B のうち F50・F52 だけは、F47 の一部として最小限を作る（決定5）。

## 2. 資料の優先順位

| 順 | 資料 | 決めること |
|---|---|---|
| 1 | `docs/features.md`（A/B/C） | 作るかどうか（範囲） |
| 2 | `docs/requirements.md` | どう動くか（仕様）。**要件定義書を正とする** |
| 3 | `docs/db/schema_ver3.sql` | DB の構造 |
| 4 | `docs/wireframes/INDEX.md`（と画像） | 画面の参考。要件定義書と違うときは、要件定義書に従う |

- 要件定義書に書いてあっても、範囲外（B・C）の機能は作らない。
- ワイヤーフレームにあっても、要件定義書にない要素は作らない。例: 詳細画面の「契約していないサービス」の折りたたみ表示。契約外は、同じ一覧にグレーの枠線で並べる。

## 3. 決定事項

| # | 論点 | 決定 |
|---|---|---|
| 1 | 会員登録の流れ | Laravel Breeze 標準（名前・メール・パスワードを入力 → 確認メール）。`01_新規登録` と `01_新規登録_メール認証後` の流れは使わない。確認メール送信済み画面は Breeze 標準の画面を使う |
| 2 | PC レイアウト | PC 専用のワイヤーフレームは作らない。Tailwind のレスポンシブ（768px）で実装する。トップ画面の人気アニメだけ、スマホ 2列×3行 / PC 6列×1行と決める。それ以外は 375〜1920px で崩れなければよい |
| 3 | サブスクの追加・編集・削除 | 1件ずつ扱う。設定タブに一覧（削除ボタン、料金変更へのリンク）と「追加」リンクを置く。`05_マイページ＿登録済みサブスク` は、1件の追加・料金変更に使う共用フォームにする。編集できるのは月額料金だけ（サービスを変えるときは削除して追加）。月額料金は1円以上の整数 |
| 4 | 機能番号のない画面要素 | 作らない。対象: 検索結果カードの「見たいリスト・視聴済み」ボタン、「まとめて削除」 |
| 5 | A が必要とする B の最小実装 | 作るのは次の3つだけ。①F47 の取り込みバッチで、1件の取得に失敗したらその1件をスキップして続ける（F50。失敗した作品は DB に保存しない）。②同じバッチで、TMDB のレート制限（秒間約40リクエスト）を守る（F52）。③見たいリストへの追加時と、視聴済みからの差し戻し時に、優先度を「現在の最大値+1」で自動的に付ける（F36）。優先度の並び替え画面（F30）は作らない |
| 6 | SQL で値が未定義の列 | `availability_status` は TMDB の区分をそのまま使う。値の一覧は、実装時に TMDB の公式ドキュメントで確認する。`user_anime_lists.status` は「見たい」「視聴済み」の2値だけにする |
| 7 | 対応する配信サービス | 4社: Netflix・Amazon Prime Video・U-NEXT・Disney+。dアニメストアは対象外。理由: JP の provider 一覧に単独の枠が無く、近い枠 2494 は Amazon 経由の追加契約枠で、直接契約の配信状況と同じとは限らない。Amazon のチャンネル枠は、シーダーに無い provider として取り込まない。2100・1796 も登録しない（人気上位60件で、9・8 に含まれない作品が0件）。2026-09-21 追記 |
| 8 | Amazon の provider | provider 10「Amazon Video」（rent / buy にだけ出る）を、バッチで provider 9 の行として保存する。`streaming_services` は Amazon 1行のまま。理由: 寄せないと Amazon のレンタルが取り込まれず、A の F23（オレンジ枠）が動かない。F47 の実装の一部で、範囲は増やさない。`availability_status` は決定6のとおり TMDB の区分のまま。2026-09-21 追記 |

## 4. 画面の扱い（24枚）

| 扱い | 画面 |
|---|---|
| 参考にして作る（16枚） | `02_検索画面（トップ）` の4枚 / `03_検索結果一覧画面` の4枚（0件を含む） / `04_アニメ詳細画面` の2枚 / `05_マイページ` の見たいリスト・視聴済み・契約状況・設定・登録済みサブスク・退会画面 |
| Breeze 標準に置き換える（2枚） | `01_ログイン・会員登録画面`、`01_新規登録` |
| 作らない（6枚） | `01_新規登録_メール認証後`（F07）、`01_パスワードをお忘れですか`（F05）、`01_パスワードをお忘れですか_メール認証後`（F06）、`05_マイページ＿ランク順変更`（F30）、`05_マイページ＿まとめて削除`（項目なし）、`05_マイページ＿パスワード変更画面`（F08） |

## 5. 作る画面の中で作らない要素

- ログイン画面の「パスワードをお忘れですか？」（F05）
- 検索候補の追加ボタン（F14）
- 検索結果カードのサービスリンク（F19。ロゴの表示だけは作る）
- 詳細画面の配信状況フィルター（F22）、最終更新日（F24）、ジャンプナビ（F28）
- 見たいリストの契約中サービス絞り込み（F31）
- 設定タブの「パスワード変更」（F08）
- 注意: 退会（F09）は A なので作る。入口は、設定タブの「退会する」リンク1つだけ。
